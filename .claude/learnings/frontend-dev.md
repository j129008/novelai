# Frontend Dev (Lea Verou) — Learnings

Rules and patterns learned from code reviews, QA feedback, and PM feedback.

## Rules

<!-- Entries are added automatically by reviewers and retro. Format:

- [2026-03-18] Do not expose internal functions via window.* unless there is a concrete external caller. Dead global assignments are code smell. (source: Linus Torvalds)
- [2026-03-18] When adding a sticky footer to a scrollable container, use flex column layout (parent flex-direction:column, scroll area flex:1 overflow-y:auto, footer flex-shrink:0) — not position:sticky which can fail in nested scroll contexts. (source: Linus Torvalds, confirmed by PM)
- [2026-03-18] Accordion empty states must never be visually empty. When content is dynamically added (e.g. character slots), provide a visible empty state card with a clear call-to-action so users know the feature is working and what to do next. A blank accordion body = perceived broken feature. (source: Steve Jobs)
- [2026-03-18] Abstract grid pickers (e.g. position selectors) require axis context. Never render a bare NxN grid without labels, directional cues, or a shaped border that maps to the underlying coordinate space. Without context, users click randomly and blame the output. (source: Steve Jobs)
- [2026-03-18] Do not place dynamic UI chips/hints outside the accordion that triggered them. If a chip (e.g. "Add 2girls to prompt") only appears when the Characters accordion is in use, it must live inside that accordion — not in the main sidebar flow where users won't see it. (source: Steve Jobs)
- [2026-03-18] Hoist loop-invariant constants above the loop. Do not recompute fixed values (e.g. Math.floor(ROWS/2)) inside nested loops where they execute N×M times. (source: Linus Torvalds)
- [2026-03-18] Never put overflow:hidden on a container that has position:absolute children expected to overflow it (e.g. autocomplete dropdowns, tooltips). overflow:hidden clips absolutely-positioned descendants that extend past the box edge. Use max-height on the specific element that needs capping, not the parent. (source: Linus Torvalds)
- [2026-03-18] When dynamically-created list items (character cards, slots) capture their own index at creation time, that index becomes stale after earlier items are removed. Either refresh all captured indices on remove, or derive the current index from DOM position at the time of use. (source: James Whittaker)
- [2026-03-18] Placeholder text for an input field must exactly match what the code accepts. If the transformation chain only supports a single tag per input, the placeholder must not show a comma-separated list — it misleads users into producing malformed data. (source: James Whittaker)
- [2026-03-18] Never interpolate server-sourced metadata (seed, steps, dimensions, filenames) directly into innerHTML. Even in local apps this is wrong. Use createElement+textContent or Number() conversion with type verification. (source: Linus Torvalds)
- [2026-03-18] Do not rely on a default value coincidence to signal "no preference" to the backend. If a user picks grid cell (center, center) which happens to be x=0.5,y=0.5 — the same as the auto default — the backend silently ignores their explicit choice. Use an explicit boolean flag or conditional payload key to distinguish "user chose center" from "auto". (source: Linus Torvalds)
- [2026-03-18] When reading a fetch() response, always use the exact key the server returns. data.tags when the server sends {"characters": [...]} silently returns undefined; use data.characters. Cross-check every data.* access against the backend route's response_model or return dict. (source: James Whittaker)
- [2026-03-18] Sidebar control order must reflect actual usage frequency, not feature enumeration. Controls touched every generation (Characters, img2img) go above the fold; controls touched rarely (Canvas Size, Seed, Steps, Sampler) must be collapsed or compacted. Treating all controls as equal importance forces the user to hunt for critical controls past irrelevant ones. (source: Steve Jobs)
- [2026-03-18] A history/gallery view that sends the user to a different page to view a single image breaks the browsing flow. The "appreciate" use case requires a lightbox that overlays the current page with keyboard navigation — never navigate away from the gallery to preview a single item. (source: Steve Jobs)
- [2026-03-18] Recall and discovery are different cognitive modes and must not share the same UI surface. Recent/used items belong near the point of re-use (e.g. recent characters inside the Characters accordion). Discovery tools (Tag Browser) must stay clean of personal history to maintain the "try something new" mindset. (source: Steve Jobs)
- [2026-03-18] Gallery cards at minmax(160px, 1fr) produce 4-5 columns that are too small to appreciate image quality. For image galleries where the primary use is visual evaluation, use minmax(240px, 1fr) as the minimum — never go below this for AI-generated image content. (source: Steve Jobs)
- [2026-03-18] Combine rarely-changed controls (Canvas Size + Seed) into a single compact two-column row rather than giving each a full control-group block. Every vertical pixel in a sidebar is precious real estate; constant controls must not compete with frequent controls for vertical space. (source: Steve Jobs)
- [2026-03-19] Canvas overlays (draggable markers, annotations) must only render when there is actual canvas content to overlay. Rendering markers over a placeholder state creates confusion — the user has no image to reason about, so coordinates are meaningless. Gate all canvas overlays on the existence of a real image. (source: Steve Jobs)
- [2026-03-19] Never hide a non-obvious interaction (double-click to reset, long-press, etc.) without a visible affordance. At minimum, add a title tooltip. Without it, users who accidentally trigger a drag have no recovery path and no mental model of the feature. (source: Steve Jobs)
- [2026-03-19] Touch and mouse event handlers that diverge in side-effects will produce inconsistent UX across device types. If a mouse click highlights a sidebar card, the equivalent touch tap must do the same. Audit every touch/mouse handler pair for behavioral parity. (source: Steve Jobs)
- [2026-03-19] Never use hardcoded color values (white, black, #fff) in component CSS — always use design system tokens (--text-primary, --bg-deep, etc.). Hardcoded colors break theme integrity and are invisible in code review without a token audit. (source: Steve Jobs)
- [2026-03-19] Document-level event listeners (mousemove, mouseup) registered inside a drag-start handler must be cleaned up if the dragged element is destroyed before mouseup fires. If a re-render can destroy the element mid-drag, use a module-level drag state that the re-render function resets, so the document listener checks a live flag rather than referencing stale DOM. (source: Linus Torvalds)
- [2026-03-19] Do not update DOM class state inside drag-start handlers to reflect data state that has not yet changed. Visual state must reflect data state. If data only changes at drag-end (conditionally), the class must only change at drag-end. Premature class removal on mousedown causes visible flicker when the interaction turns out to be a click, not a drag. (source: Linus Torvalds)
- [2026-03-19] Comments that describe behavior the code does not implement are actively harmful — they make reviewers trust the code is complete when it is not. Either implement the described behavior or delete the comment. Zero tolerance for comment/code drift. (source: Linus Torvalds)
- [2026-03-19] Never unconditionally clear shared state (arrays, DOM containers) at the start of a restore/load operation. Always check whether the incoming data actually has replacement content first. Unconditional clears silently destroy user data when the source has no replacement — e.g., clearing character slots when loading settings from an image that was generated without characters. (source: James Whittaker)
- [2026-03-19] When a factory function (e.g. buildInteractionsSection) creates a UI widget for a data object that may already have pre-existing sub-data (e.g. charData.interactions), it must render those existing entries on creation — not just provide an add-new UI. Failing to pre-populate makes restored data invisible to the user. (source: James Whittaker)
- [2026-03-20] A sidebar is not a settings panel. It is a creative tool. Controls that are touched every generation must be immediately visible without scrolling. Controls that are configured once per session must be removed from the main sidebar flow entirely — use a popover, modal, or drawer — not another accordion in the same scroll column. Repeated user complaints about sidebar crowding signal a structural failure, not a cosmetic one. (source: Steve Jobs)
- [2026-03-20] When a sidebar has more than 3–4 control groups, stop adding compact rows and start asking what does not belong in a sidebar at all. The answer is almost always "everything except the primary creative input and the thing the user changes most often." Configuration belongs in a popover triggered by a single compact row. (source: Steve Jobs)
- [2026-03-20] A popover for secondary controls should be anchored and constrained — position:absolute inside the parent sidebar container, never position:fixed. Fixed popovers escape their parent and create z-index and clipping bugs across breakpoints. (source: Steve Jobs)
- [2026-03-20] Setting canvas.width or canvas.height clears ALL content (HTML5 spec). If a ResizeObserver or resize handler sets dimensions, guard with `if (canvas.width === newW && canvas.height === newH) return` — otherwise every observer tick erases user-drawn strokes. (source: David, user bug report)
- [2026-03-20] Never call a full re-render (destroy + recreate DOM) inside a single-click handler if the element supports dblclick. The second click lands on a new element and the browser cannot fire dblclick. Update classes in-place on single click; only re-render on state changes that alter the element count. (source: David, user bug report)
- [2026-03-20] When loadSettingsFromMeta accesses optional DOM elements (hidden controls, removed features), every access must be null-guarded. A single null.checked TypeError crashes the entire function and prevents all subsequent code (like character restoration) from running. (source: David, console error)
- [2026-03-20] When a "Load" action restores settings from a secondary view (History, Lightbox), always auto-switch to the primary working view (Canvas tab) afterward. Leaving the user on a non-actionable tab after loading forces unnecessary manual navigation. (source: David, user feedback)
- [2026-03-20] When adding automatic behavior that replaces a manual action (e.g., auto-insert image at cursor replaces Insert Image button), immediately remove the now-redundant manual control. Leaving dead buttons creates confusion about which is the "real" way to do things. (source: David, user feedback)
- [2026-03-20] When a render function iterates a backend response with Object.entries(), the parameter must be an object keyed by category, not a flat array. If the API returns a flat list, group it by a field (e.g. category) client-side before passing to the renderer — or change the renderer to iterate the array directly. Never pass a flat array to a dict-iteration renderer. (source: James Whittaker)
- [2026-03-20] When reading fields from backend response objects, use the exact field name from the response_model schema. item.tag is undefined if the schema declares name — use item.name. Always cross-check every object property access against the Pydantic schema's field names. (source: James Whittaker)
- [2026-03-20] removeTagFromPrompt must handle the solo-tag case: a prompt containing exactly the tag with no commas. Both the leading-comma pattern and the trailing-comma pattern miss this case. Add a fallback: if the cleaned value still equals the original tag, set value to empty string. (source: James Whittaker)
- [2026-03-20] When removing large code blocks, delete them entirely — do not wrap in dead-function wrappers or block comments. Commented-out code with mismatched braces causes syntax errors; dead functions with `return` at the top still occupy scope and confuse IDEs. (source: Linus Torvalds, syntax error)
- [2026-03-20] contentEditable with embedded non-editable blocks (figures, cards) is inherently fragile. Use MutationObserver to re-enforce contentEditable=false on protected elements, event delegation for action buttons (they survive DOM mutations), and pointer-events:none on images to prevent browser resize handles. (source: David, user bug report)
- [2026-03-20] When building a feature that has multiple card-building code paths (new, cache restore, load from metadata), either extract a shared builder function or ensure every code path includes all interactive elements (reorder buttons, delete buttons, etc.). Missing buttons on cached/restored items is a recurring bug. (source: David, repeated bug reports)
- [2026-03-21] A panel class that specifies flex-direction and gap without display:flex is broken — those properties only apply when the element is a flex container. When cloning a panel pattern (e.g. canvas-panel → craft-panel), always copy display:flex and flex:1 along with flex-direction and gap. (source: Linus Torvalds)
- [2026-03-21] When a fetch-and-poll loop uses setTimeout to reschedule itself, it must carry a cancellation token (e.g. a generation counter) that is checked before each reschedule. Without it, dropping a new file or starting a new analysis while polling creates concurrent loops that corrupt shared DOM state. (source: Linus Torvalds)
- [2026-03-21] Never set a label immediately before calling a shared reset function that unconditionally overwrites that same label. In a finally block, either call reset first then set the label, or pass the desired label as a parameter to the reset function. (source: James Whittaker)
- [2026-03-21] When a backend Literal type defines the full set of valid enum values, the corresponding HTML <select> must contain exactly those options — no more, no fewer. Omitting valid options silently prevents users from submitting them without any error feedback. (source: James Whittaker)
- [2026-03-21] Every long-running async generation path (image, video, any provider) must schedule a stopTimeout that transitions the button to "stopping" state. Without it the user has no cancel path and is stuck until the request completes or times out. (source: Linus Torvalds)
- [2026-03-21] When a generation function sets canvasImageBase64 but not canvasImageWidth/Height, downstream code that uses those dimensions (e.g. the crop overlay) will operate on stale dimensions from a prior generation. Always null out dimension state when the new generation has no known pixel dimensions. (source: Linus Torvalds)
- [2026-03-21] A config bar that collapses five or more fields into a single horizontal strip will inevitably overflow at 340px sidebar width. Provider switching must be the escape hatch — each mode gets exactly the fields it needs, not the union of all modes' fields simultaneously. Never design a config bar around the maximum possible field count. (source: Steve Jobs)
- [2026-03-21] When provider switching hides/shows controls via display:none, controls that are always-applicable (Seed, Generation Settings gear) must never be hidden. Only controls that are model-specific should participate in the show/hide dance. (source: Steve Jobs)
- [2026-03-21] A video element in a lightbox must have its src explicitly cleared (video.src = "") before display:none is applied, otherwise autoplay continues playing audio invisibly. Always pair closeLightbox with an explicit src reset, not just display:none. (source: Steve Jobs)
- [2026-03-21] A source/reference thumbnail on the canvas output area positioned at bottom-left at 64x64px with 0.75 opacity is invisible to most users. If showing "what was used to generate this" is valuable, give it a persistent mini-panel below the output image, not an overlaid semi-transparent thumbnail that fights with the generated art. (source: Steve Jobs)
- [2026-03-21] Provider-mode context collapse: when switching from NovelAI to Grok, the sidebar must not show Grok-specific controls (Image/Video toggle, quota bar) scattered between NovelAI controls that are hidden. Group all mode-specific controls in one contiguous zone so the sidebar reads as a coherent unit per mode. (source: Steve Jobs)
- [2026-03-21] Placeholder state must indicate drag-and-drop availability. A placeholder that says "Press Generate or Enter" with no visual affordance for drag-to-use misses 100% of users who have an image they want to iterate from. The placeholder is the most seen surface in the app — it must teach. (source: Steve Jobs)
- [2026-03-21] Application chrome (button labels, placeholder text, status text, accordion hints) must be in a single consistent language. Mixing languages in the UI — even if the developer's primary language differs — is unprofessional and confusing. The Prompt Guide can be in any language since it is a reference document; the interactive UI cannot be. (source: Steve Jobs)
- [2026-03-21] Never use emoji as the sole content of a UI button when the rest of the app uses SVG stroke icons. An emoji in a button is not a design choice — it is a placeholder that was never replaced. Create a proper SVG icon that matches the app's visual language. (source: Steve Jobs)
- [2026-03-22] Never define the same CSS selector twice in the same stylesheet, even if the second occurrence is labeled "legacy" or "kept for compat." The later definition wins at equal specificity and silently overrides the earlier one. Before adding a new rule for an existing selector, grep for the selector and either update the existing rule in place or delete the legacy block entirely. (source: James Whittaker)
- [2026-03-22] When a shared keydown handler (e.g. tag autocomplete dropdown) handles Escape by calling hide() without e.stopPropagation(), any document-level Escape handler will also fire. Inside a modal, this means a single Escape press dismisses the dropdown AND closes the modal. Always call e.stopPropagation() in child Escape handlers when the modal should remain open. (source: James Whittaker)
- [2026-03-22] CSS animations on persistent DOM elements (shown/hidden via display toggle) only fire once — on first show. Subsequent opens skip the animation because the element's animation is already in the "finished" state. Force replay on re-open with: el.style.animation="none"; void el.offsetWidth; el.style.animation=""; (source: James Whittaker)
- [2026-03-22] Never create a new Image(), set img.src to a data URL, and immediately read img.naturalWidth without awaiting onload. Chromium resolves data URLs synchronously in practice, but Firefox does not guarantee this. The safe pattern is: await new Promise(resolve => { img.onload = resolve; img.src = dataUrl; }). Using naturalWidth = 0 silently causes NaN math and blank canvas output. (source: James Whittaker)
- [2026-03-22] Every code path that adds items to a capped array (e.g. MAX_LAYERS) must check the cap independently. A MAX guard on "Add Layer" does not protect against "Send to Layer" — both push to the same array. Enforce the cap in a shared helper, not at each call site. (source: James Whittaker)
- [2026-03-22] When a parent element has draggable="true" and a child has contentEditable="true", add a dragstart handler on the child that calls e.stopPropagation(). Without it, any attempt to drag-select text in the editable field initiates a row drag instead, making mouse-based renaming non-functional. (source: James Whittaker)
- [2026-03-22] Mask editor mode labels must name the outcome, not the drawing operation. "Reveal"/"Hide" are self-evident; "Paint"/"Erase" are ambiguous in the mask context and require documentation to interpret. (source: Steve Jobs)
- [2026-03-22] A mask editor's visual overlay must show hidden areas in a high-contrast tint (red at ~0.55 opacity) over the source image, and show revealed areas as the unobstructed source. Semi-transparent white/black overlays on both states provide no clear boundary and are invisible against dark backgrounds. (source: Steve Jobs)
- [2026-03-22] When two controls in different sections jointly control a single outcome (e.g. layer opacity + i2i strength both affect "how much the AI follows this layer"), add a cross-reference hint near the less-obvious control pointing to the primary one. Never duplicate sliders — one source of truth, one pointer. (source: Steve Jobs)
- [2026-03-22] Button labels for destructive or "removal" modes (hide, delete, mute) must use danger color tokens (--danger, --danger-bg, --danger-border) to signal irreversibility visually. A neutral grey button for a hide/erase mode communicates nothing about the consequence. (source: Steve Jobs)
- [2026-03-22] Never define two component patterns for the same UI widget (e.g. two toggle switch systems) in the same stylesheet. The old pattern becomes an invisible trap — any developer who copies it gets broken output with no error. Delete old patterns completely at the moment the new one is adopted. (source: Steve Jobs)
- [2026-03-22] When two sibling flex children both declare margin-left:auto, only the first meaningfully pushes to the right edge; the second has no space left to consume. Assign margin-left:auto only to the first push-element; use gap or a spacer between siblings thereafter. (source: Steve Jobs)
- [2026-03-22] A shared CSS class used by two structurally different overlays (e.g. .guide-overlay for both a reference panel and a settings modal) is a fragile coupling. If the class is modified for one use case, it silently breaks the other. Give each overlay a dedicated class. (source: Steve Jobs)
- [2026-03-22] When writing a localStorage save/load round-trip for an array of objects, enumerate EVERY field of the in-memory object in the load function's push() call. Any field omitted from the load path silently defaults to undefined on the next page load. Store the canonical field list as a comment adjacent to the array declaration and verify the load function against it during code review. (source: James Whittaker)
- [2026-03-22] A config bar separator element (id="provider-sep") must be hidden together with the element it visually separates. If canvas-field is hidden on Grok mode, its preceding separator must also be hidden. Treat separator visibility as a dependency of the adjacent field visibility, not as a standalone concern. (source: James Whittaker)
- [2026-03-22] e.stopPropagation() does NOT prevent independently-registered listeners on the same node from firing. In a modal with a document Escape handler and a dropdown inside with its own document keydown handler, both fire on Escape. The fix is e.stopImmediatePropagation() in the inner handler, or a guard at the top of the outer handler that checks if the dropdown is visible and returns early. (source: James Whittaker)
- [2026-03-24] The Explore tab is an on-ramp to generation, not a browsing product. Extending it to browse local folders is coherent with its purpose; embedding a multi-site download manager (e.g. ComicCrawler) is not. Features that expand the product into dependency-heavy adjacent domains (download management, credential storage) must be rejected in favor of the minimal version that solves the user's actual pain. (source: Steve Jobs)
- [2026-03-24] A canvas image fit prompt (fit / crop / keep) when an imported image differs from canvas dimensions is a universal quality-of-life improvement that applies to every image source — paste, drag-drop, file picker, Explore. Spec it as a standalone feature independent of any image source integration. (source: Steve Jobs)
- [2026-03-25] Never place interactive UI panels (analysis, detail views, settings) after unbounded scrollable content (e.g. an image grid with thousands of items). The panel will be unreachable. Use a modal overlay or fixed/sticky element instead. (source: David, "你放在畫面最底部... 這也太智障了")
- [2026-03-25] Tab/toggle active states must use high-contrast filled styling (accent background + white text), not subtle border-only changes. Users must instantly see which tab is active without comparing. The previous approach (border-top color change only) was invisible. (source: David, "爛死了這個")
- [2026-03-25] Modal overlay backdrops must be nearly opaque (>=0.9 opacity) when the modal content needs focus. Semi-transparent backdrops (0.75) let busy background content show through and create visual noise. (source: David, "哪個透明設計讓畫面很亂")
- [2026-03-25] When adding new CSS for scroll containers, always verify the overflow property on BOTH the container and its parent. A child with overflow-y:auto inside a flex parent without min-height:0 will not scroll. Test with actual content volume, not just a few items. (source: David, "結果不能捲動啊")
- [2026-03-25] After modifying JS/CSS files, always bump the cache-busting version parameter (?v=N) in the HTML script/link tags. Users will see stale behavior otherwise and report bugs that don't exist in the code. (source: David, confusion from cached old JS)
- [2026-03-25] Any operation that silently overwrites user-typed content (optimize, autocomplete replace, tag rewrite) must save the previous value to history before replacing it. Users must always have a one-step recovery path. Never destroy unreplicated user input without a save. (source: Steve Jobs)
- [2026-03-25] Every button that uses btn.disabled = true during an async operation must have a corresponding CSS :disabled rule that visually reflects the state (opacity reduction + cursor:not-allowed). A button that is functionally disabled but visually identical gives the user no feedback — they click again, nothing happens, and they cannot tell if the app is broken. (source: Steve Jobs)
- [2026-03-25] A feature tab that is never used signals a navigation architecture failure, not a user preference issue. If a tab is consistently unused, it means the feature is either unreachable from the natural workflow, duplicated elsewhere, or solving the wrong problem. Remove it rather than redesign it. Dead tabs impose cognitive cost on every interaction. (source: Steve Jobs)
- [2026-03-25] A tab that opens a tool panel (analysis, configuration, auxiliary tool) is architecturally wrong. Tabs should be destinations (Canvas, History, Gallery). Tools should be triggered from within those destinations via buttons, overlays, or drawers. Never make a tool a top-level navigation destination. (source: Steve Jobs)
- [2026-03-25] The image action bar is a critical workflow moment — the user just got a result and must decide what to do next. Showing 6–8 buttons at once destroys decision speed. Cap visible primary actions at 3 (Download, Reuse Seed, one contextual iteration action). Anything beyond that belongs in an overflow menu. (source: Steve Jobs)
- [2026-03-25] Icon-only buttons without visible text labels fail for any user who has not already learned the app. In a creative tool where the primary user is a first-time or occasional user, all action buttons in the main flow must show text. Icon-only is acceptable only in high-frequency, spatially-constrained contexts (e.g. close buttons, toolbar toggles) where the icon is universally recognizable. (source: Steve Jobs)
- [2026-03-27] Never assign --primary (accent) styling to a button whose action is redundant given the user's configuration. If auto-save is configured, Download is not the primary action — it should be demoted to overflow or ghost styling. Action prominence must reflect actual workflow necessity, not feature completeness. (source: Steve Jobs)
- [2026-03-27] The overflow toggle (...) button must use the base ghost style (btn-action), never a danger variant. The overflow indicator communicates "more options exist" — using danger styling incorrectly signals destructive intent and teaches the user to avoid it. (source: Steve Jobs)
- [2026-03-27] Context-sensitive actions (e.g. Send to Layer, which only applies when layers exist and NovelAI is active) must be promoted to primary visibility when their context is active, and hidden entirely when it is not. Hiding them always in overflow defeats the purpose of context sensitivity. (source: Steve Jobs)
- [2026-03-27] A floating panel that permanently overlays the canvas is the wrong pattern for any canvas-centric tool. The canvas is the product — nothing should permanently occlude it. Floating panels must either collapse to a minimal pill, anchor below the canvas, or move their controls into the sidebar. (source: Steve Jobs)
- [2026-03-27] Controls that require precise slider interaction (opacity, scale) do not belong in a floating canvas overlay where the panel itself may need to be moved to access the underlying content. Sliders are sidebar controls — they require stable, non-overlapping screen real estate. (source: Steve Jobs)
- [2026-03-27] When a setup function toggles a button's icon state using collapseBtn.textContent = '▾', it silently destroys any SVG child nodes that were placed in the HTML. Use innerHTML with the full SVG markup when the icon is SVG, never textContent. This regression pattern is easy to miss because the button still works — it just renders wrong. (source: James Whittaker)
- [2026-03-27] When an init function restores state (e.g. from localStorage) and renders UI but does NOT call the full panel-update function, ensure any sub-elements that should be conditionally hidden have safe default visibility in the HTML (e.g. style="display:none"). Otherwise they remain visible until the next user interaction triggers the update path. (source: James Whittaker)
- [2026-03-27] Async buttons that use btn.disabled=true for loading state must also show an in-place visual spinner — not rely on a spatially-disconnected status toast. The toast is a secondary confirmation; the button itself is the primary feedback surface. Apply a .loading class with a CSS ::after spinner, not just opacity. (source: Steve Jobs)
- [2026-03-27] Dynamic textarea height (auto-grow on input) must be triggered on initial render for restored/pre-populated content, not only on user input events. If ta.value is set programmatically, immediately follow with: ta.style.height="auto"; ta.style.height=ta.scrollHeight+"px". Failing to do this clips previously-saved content silently. (source: Steve Jobs)
- [2026-03-27] When a factory function creates UI cards in two separate code paths (new card vs. cache restore), the rows attribute and min-height behavior must be identical. Inconsistent sizing between new and restored cards signals the restore path was added as an afterthought and never fully audited against the new-card path. (source: Steve Jobs)
- [2026-03-27] Status messages after AI rewrites (optimize, refine) must be descriptive of what changed, not just confirm that something happened. "Prompt optimized" is meaningless. "Tags reordered and formatted" or surfacing data.changes from the API gives the user actionable context. (source: Steve Jobs)
- [2026-03-27] When writing a tag-parsing function that strips NovelAI weight syntax (e.g. 1.5::tag::), use two separate regexes: /^[\d.]+::/ for the leading weight prefix, and /::$/ for the bare trailing close delimiter. Do NOT use /::[\d.]+$/ for the trailing delimiter — it requires digits after :: which the syntax does not include. Also handle negative prefixes separately with /^-[\d.]+::/. Cross-check against any sibling strip function (e.g. recordRecentCharacters in tags.js) before shipping. (source: James Whittaker)
- [2026-03-27] When a sidebar accumulates controls over time, the correct fix is structural reorganization — not compaction. Group controls by usage frequency: (1) primary creative input always visible, (2) per-generation tweaks in a collapsible accordion with a live-value badge, (3) one-time configuration in a popover.
